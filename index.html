Medallion Data Architecture Pipeline

Tiered storage layers from immutable raw landing to dimensional business marts.

STAGE 1 • LANDING
MinIO Raw S3
Immutable landing zone storing multi-part raw CSV ingestion partitioned by date.
  • Partition: year/month/day
  • Boto3 multipart upload
  • Quarantine isolation
STAGE 2 • BRONZE
Delta Lake Ingestion
Append-only raw clickstream events with strictly enforced schema and dead-letter routing.
  • ACID transaction log
  • Permissive parser mode
  • Soda Core pre-checks
STAGE 3 • SILVER
Delta Lake MERGE
Incremental merge with watermark lookback, SHA-256 deduplication, and category parsing.
  • SHA-256 fingerprinting
  • Category hierarchy (L1/L2/L3)
  • Sub-second row lookup
STAGE 4 • GOLD
dbt & DuckDB Warehouse
Dimensional star schema modeling, SCD Type 2 product validity, and 30-min sessionization.
  • dim_customer & dim_product
  • fact_events & fact_purchases
  • 57 dbt tests passed
STAGE 5 • MARTS
Business Marts & BI
Pre-aggregated dimensional marts driving daily revenue summaries and retention matrices.
  • mart_daily_summary
  • mart_customer_retention
  • mart_category_performance

Architectural Decision Records (ADRs)

Technical trade-offs and design rationale.

ADR-001 • STORAGE
MinIO S3A vs Local Files
Adopted S3-compatible MinIO object storage with explicit date partitioning for cloud architecture simulation and zero local FS locking.
ADR-002 • TABLE FORMAT
Delta Lake ACID MERGE
Replaced plain Parquet with Delta Lake format to gain ACID transactions, atomic MERGE upserts, and SHA-256 deduplication.
ADR-003 • SQL ENGINE
DuckDB In-Process Engine
Selected DuckDB to execute all Gold dimensional models locally with column-store execution and direct Delta Lake scanning.
ADR-004 • GOVERNANCE
Versioned YAML Contracts
Adopted proactive schema contracts with dead-letter quarantine routing to catch bad schemas before polluting downstream analytics.
