Architectural Decision Records (ADRs)

Core technical tradeoffs and architectural design rationale

ADR-001 • STORAGE
MinIO S3A vs Local Filesystem
Adopted S3-compatible MinIO object storage with explicit date partitioning for realistic cloud architecture simulation and zero local FS locking.
ADR-002 • TABLE FORMAT
Delta Lake ACID MERGE
Replaced plain Parquet with Delta Lake format to gain ACID transactions, atomic MERGE upserts, and SHA-256 deduplication.
ADR-003 • SQL ENGINE
DuckDB In-Process Engine for dbt
Selected DuckDB to execute all Gold dimensional models locally with ultra-fast column-store execution and direct Delta Lake scanning.
ADR-004 • GOVERNANCE
Versioned YAML Data Contracts
Adopted proactive schema contracts with dead-letter quarantine routing to catch bad schemas before polluting downstream analytics.
